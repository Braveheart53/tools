NVIDIA GPU Exporter (Windows)

Expose NVML/SMI telemetry to Prometheus. Compatible with Tesla, RTX, and data center architectures.

1. Install & Configure

Corrected in v0.0.6

The previous command downloaded from prometheus-community/nvidia_gpu_exporter, a repository that does not exist. The exporter is utkuozdemir/nvidia_gpu_exporter. It installs through winget and registers itself as a native Windows service, so no NSSM or New-Service step is needed[56].

# Install machine-wide, then register the native service with the NVML backend
winget install --scope machine utkuozdemir.nvidia_gpu_exporter
nvidia_gpu_exporter install --collect.backend=nvml
Start-Service nvidia_gpu_exporter

# Let Prometheus on another machine on the subnet scrape port 9835
New-NetFirewallRule -DisplayName "Nvidia GPU Exporter" -Direction Inbound -Action Allow `
    -Protocol TCP -LocalPort 9835 -Profile Private,Domain -RemoteAddress LocalSubnet

2. Verify Telemetry

Visit http://localhost:9835/metrics. Confirm key time-series:

  • nvidia_smi_utilization_gpu_ratio
  • nvidia_smi_memory_used_bytes / nvidia_smi_memory_total_bytes
  • nvidia_smi_power_draw_watts, nvidia_smi_temperature_gpu names corrected in v0.0.6[20]
ℹ️ Prometheus Config Snippet:
scrape_configs:
- job_name: 'nvidia-gpu'
static_configs: [{targets: ['localhost:9835']}

AMD GPU Exporter (ROCm / Windows)

Corrected in v0.0.6

This section previously installed prometheus-community/amd-rocm-exporter and listed rocm_* metrics. That repository does not exist, and no exporter publishing those metric names could be found. AMD's own exporter, amd_smi_exporter, receives no further updates and is Linux-only[57], and amd-smi is not supported under WSL[53], so the WSL bridge in the folder's notes cannot report the GPU either. The route below works for AMD (and NVIDIA and Intel) GPUs on Windows. Full background: GPU configuration, section 13.

📦 Exporter Setup

# gpu collector: vendor-neutral Windows
# GPU counters, off by default
.\windows_exporter.exe `
  --collectors.enabled "[defaults],gpu"

# Or from the MSI:
msiexec /i windows_exporter.msi `
  --% ENABLED_COLLECTORS="[defaults],gpu"

📊 Key Metrics

  • windows_gpu_engine_time_seconds_total (busy time per engine; use rate())
  • windows_gpu_adapter_memory_dedicated_bytes and its usage counterparts
  • Temperature and power sensors where the driver exposes them (0.32.x)

Prometheus Target Config

- job_name: 'windows-gpu'
  static_configs: [{targets: ['localhost:9182']}]
ℹ️ Note: the engine counter is named windows_gpu_engine_time_seconds in windows_exporter 0.31.7 (the version in the folder) and gains _total in 0.32.x. On a Linux host with ROCm, use AMD's Device Metrics Exporter[58] instead.

Grafana Dashboard Configuration

Unified visualization for both NVIDIA and AMD telemetry. Import official community dashboards or build custom panels.

1. Add Prometheus Data Source

  1. Configuration > Data Sources > Add source > Prometheus
  2. Set URL: http://localhost:9090 (or your cluster endpoint)
  3. Click Save & Test. Green checkmark = confirmed connectivity.

2. Import GPU Dashboards

🟢 NVIDIA Dashboard

Dashboard ID: 14574 corrected in v0.0.6: the exporter's README names 14574, plus 25547 for a multi-GPU overview[20]

  1. Create > Import in Grafana
  2. Paste ID or upload JSON
  3. Select your Prometheus DS
  4. Click Import

🔵 AMD Dashboard

No published dashboard confirmed. corrected in v0.0.6

  1. The earlier dashboard ID mapped to a rocm_* namespace no exporter publishes
  2. Build a panel from sum by (phys) (rate(windows_gpu_engine_time_seconds_total{phys="0", engtype="3D"}[1m])) * 100[55]
  3. List the engine types your driver reports with count by (engtype) (windows_gpu_engine_time_seconds_total)

3. Troubleshooting & Customization

  • No Data? Check Grafana time range (last 5-10 mins), verify exporter service status, and confirm Prometheus scrape targets are UP.
  • Multigpu Filtering: Edit panel query → Add label matchers: {device=~"0|1|2"}
  • Custom Alerts: Use PromQL thresholds like nvidia_smi_power_draw_watts > 350 corrected in v0.0.6: power is a gauge, so rate() does not apply (see counters and gauges); the rocm_* metric does not exist

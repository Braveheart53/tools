Step 1 · Software and downloads

Everything to install, and where to get it

Every program the deployment uses, linked to its original creator's download page, with the version found in the deployment folder beside the newest one published on 2026-11-15. Six of the programs in the folder are not in the GitHub repository, because their installers are too large for it, so a reader who clones the repository has to fetch those from the publisher. They are listed first.

Download from the publisher, not from a mirror: an installer that runs as administrator and loads a kernel driver is the wrong place to save a click. Where a publisher ships source only, the row names the distributor the publisher's own documentation points to and says so.

5. How the versions were checked

  • In the folder is read from the installer and archive file names in tools/AI_Local on 2026-11-15. It is what was installed from, not a recommendation.
  • Current for GitHub-hosted projects is the highest release tag in the repository, read with git ls-remote --tags; for the others, the publisher's download or release-notes page cited in the row.
  • Newer available appears only where both columns are plain version numbers. A row without it has not been judged, not judged current.
  • Every link on this page and across the set can be re-checked with python scripts/check_links.py, which reports links that no longer resolve.

Version numbers move weekly. Treat the Current column as the state on 2026-11-15 and the link as the thing to trust.

Open WebUI + Jupyter GPU Server Setup

Complete, explicit guide to deploying GPU-accelerated Jupyter servers inside WSL2 (Ubuntu), bridged to Open WebUI via Docker Desktop on Windows 10/11. Managed as persistent Windows services with NSSM. Uses Micromamba for environment management.

📅 Updated: 2025⏱️ ~60 min read🐍 Micromamba🖥️ Windows + WSL2🛠️ NSSM + PowerShell

Select your GPU ecosystem to proceed:

✅ Step 1: Windows WSL2 Prerequisites

1

Install WSL2 & Ubuntu Distro

PowerShell (Admin)
PS C:\> wsl --install -d Ubuntu-24.04
PS C:\> wsl --set-default-version 2
# Reboot if prompted
2

Install Docker Desktop (Windows Host)

  • Download Docker Desktop from docker.com/products/docker-desktop
  • During install, check "Use WSL 2 instead of Hyper-V"
  • Launch Docker Desktop → Settings → General → Ensure "Use the WSL 2 based engine" is checked
  • Go to Resources → WSL Integration and enable Ubuntu
3

Verify WSL2 & Docker Integration

PowerShell & WSL2
# Windows Host:
PS C:\> wsl --list --running
PS C:\> docker info | grep -i "WSL"

# WSL2 Ubuntu Terminal:
$ docker run hello-world  # Should pull and run successfully via WSL2 engine

🐍 Step 2: Install Micromamba (WSL2 Ubuntu)

Micromamba is a standalone, fast binary for environment management. It replaces traditional conda/mamba entirely.

WSL2 Ubuntu
# 1. Download micromamba binary
$ curl -Ls https://micro.mamba.pm/api/micromamba/linux-64/latest | tar -xvj bin/micromamba

# 2. Move to system path
$ sudo mkdir -p /usr/local/bin && sudo mv bin/micromamba /usr/local/bin/ && rm -rf bin

# 3. Initialize shell integration
$ micromamba shell init -s bash -p $HOME/.micromamba
$ echo 'export PATH="$HOME/.micromamba/bin:$PATH"' >> ~/.bashrc
$ source ~/.bashrc

# 4. Verify installation
$ micromamba --version   # Should output: x.x.x
$ micromamba config set channel_priority strict
$ micromamba config add channels conda-forge

💚 NVIDIA CUDA Path

1

Install Windows GPU Driver & WSL2 CUDA Support

PowerShell (Admin)
# 1. Install NVIDIA GameReady/Studio Driver ≥ 535 (CUDA 12.x) or ≥ 550 (CUDA 12.4+)
PS C:\> winget install --id NVIDIA.Driver
# Reboot Windows after driver installation

# 2. Update WSL2 kernel to expose GPU passthrough
PS C:\> wsl --update
PS C:\> wsl --shutdown  # Restart all distros to apply changes
2

Verify GPU Passthrough in WSL2

WSL2 Ubuntu
# Inside WSL2 terminal:
$ nvidia-smi   # Must show Windows host driver version & WSL2 CUDA runtime
$ cat /proc/driver/nvidia/version
$ echo $CUDA_HOME  # Should be empty or /usr/local/cuda if installed later

Configure ROCm Kernel Modules in WSL2

WSL2 Ubuntu
# Install ROCm WSL2 kernel modules & utilities
$ sudo apt update && sudo apt install -y linux-modules-extra-$(uname -r) rocm-dkms rocm-smi-lib
# Enable ROCm support in WSL2 kernel
$ echo "options amdgpu si_support=1" | sudo tee /etc/modprobe.d/amdgpu.conf
$ sudo update-initramfs -u
$ sudo shutdown -r now  # Reboot WSL2

📓 Step 3: Jupyter Server Configuration (WSL2)

Identical for both paths. Generates token, binds to all interfaces, and installs GPU kernel.

WSL2 Bash
# 1. Generate configuration file
$ jupyter lab --generate-config

# 2. Generate secure token & password hash
$ python -c "from jupyter_server.auth import passwd; print(passwd('your_strong_password', 'argon2'))" # Save output
$ python -c "import secrets; print(secrets.token_urlsafe(32))" # Use as JUPYTER_API_TOKEN later
~/.jupyter/jupyter_lab_config.py
# ~/.jupyter/jupyter_lab_config.py (NVIDIA Path)
c.ServerApp.ip = "0.0.0.0"
c.ServerApp.port = 8888
c.ServerApp.open_browser = False
c.ServerApp.allow_remote_access = True
c.ServerApp.allow_root = True
c.ServerApp.disable_check_xsrf = True

🐳 Step 4: Open WebUI (Docker Desktop on Windows Host)

Open WebUI runs on the Windows host via Docker Desktop. It connects to WSL2 Jupyter via cross-OS networking.

docker-compose.yml (Windows Host)
# docker-compose.yml (Save to C:\Projects\open-webui\)
version: "3.8"
services:
  open-webui:
    image: "ghcr.io/open-webui/open-webui:main"
    container_name: open-webui
    restart: unless-stopped
    ports:
      "- 3000:8080"
    volumes:
      "- open-webui-data:/app/backend/data"
    environment:
      # WSL2 Jupyter IP will be set in Step 6 (Networking)
      "JUPYTER_SERVER_URL": "http://WSL2_HOST_IP:8888"
      "JUPYTER_API_TOKEN": "YOUR_GENERATED_TOKEN"
      "WEBUI_AUTH": "true"
      "ENABLE_OAUTH_SIGNUP": "true"
      "DEFAULT_LOCALE": "en"
    networks:
      - win-docker-net

volumes:
  open-webui-data:
networks:
  win-docker-net:
    driver: nat
PowerShell
# Start Open WebUI on Windows Host
PS C:\> cd C:\Projects\open-webui
PS C:\Projects\open-webui> docker compose up -d
# Access at: http://localhost:3000

🛠️ Step 5: NSSM Service Bridge (PowerShell)

Run WSL2 Jupyter as a persistent Windows service using NSSM. Wrapper script handles WSL2 environment isolation.

start-jupyter-wsl2.ps1
# C:\Scripts\start-jupyter-wsl2.ps1 (NVIDIA Path)
$env:JUPYTER_USER = "yourusername"
$env:WSL_DISTRO = "Ubuntu-24.04"
$env:JUPYTER_TOKEN = "YOUR_GENERATED_TOKEN"

while (-true) {
    try {
        Write-Host "[INFO] Starting Jupyter Server..." -ForegroundColor Green
        $exitCode = wsl -d $env:WSL_DISTRO -u $env:JUPYTER_USER \
            "/home/$($env:JUPYTER_USER)/micromamba/envs/jupyter-gpu/bin/python" \
            -m ipykernel_launcher -f "/dev/null" --ip "0.0.0.0" --port 8888 \
            --no-browser --allow-root --NotebookApp.token="$env:JUPYTER_TOKEN"
    } catch {
        Write-Host "[ERROR] Jupyter crashed. Restarting in 5s..." -ForegroundColor Red
    }
    Start-Sleep 5
}
PowerShell (Service Install)
# Install NSSM if not present: https://nssm.cc/download
$NSSM_PATH = "C:\Program Files\nssm\bin\win64\nssm.exe"

# NVIDIA Service
New-Item "C:\Logs" -ItemType Directory -Force
PS C:\> & "$NSSM_PATH" install "JupyterWSL2GPU" "powershell.exe" "-ExecutionPolicy Bypass -File C:\Scripts\start-jupyter-wsl2.ps1"
PS C:\> & "$NSSM_PATH" set "JupyterWSL2GPU" AppStdout "C:\Logs\jupyter.out.log"
PS C:\> & "$NSSM_PATH" set "JupyterWSL2GPU" AppStderr "C:\Logs\jupyter.err.log"
PS C:\> & "$NSSM_PATH" start "JupyterWSL2GPU"

# Verify service status
PS C:\> Get-Service JupyterWSL2GPU

🌐 Step 6: Windows ↔ WSL2 Networking

Docker Desktop (Windows) must reach Jupyter (WSL2). Use reliable vEthernet bridge IP.

PowerShell (Get IP)
# Get reliable WSL2 host IP for Docker Desktop
PS C:\> $wslip = (Get-NetIPAddress -InterfaceAlias "vEthernet (WSL)" | Select-Object -ExpandProperty IPAddress)
PS C:\> Write-Host "Use this IP in docker-compose.yml for JUPYTER_SERVER_URL: $wslip"
PowerShell (Firewall Rules)
# Open Windows Firewall for Docker & Jupyter
PS C:\> New-NetFirewallRule -DisplayName "Open WebUI" -Direction Inbound -Protocol TCP -LocalPort 3000 -Action Allow
PS C:\> New-NetFirewallRule -DisplayName "WSL2 Jupyter Bridge" -Direction Inbound -Protocol TCP -LocalPort 8888 -RemoteAddress Any -Action Allow

🔧 Step 8: Troubleshooting

IssueNVIDIA Path FixAMD Path FixWindows/WSL2 Fix
CUDA/HIP not available in WSL2Update Windows GPU driver ≥535 + `wsl --update`Run `sudo apt install rocm-dkms` + reboot hostDocker Desktop → Resources → WSL Integration → Enable Ubuntu
Docker can't reach JupyterUse `Get-NetIPAddress -InterfaceAlias "vEthernet (WSL)"` IP in `JUPYTER_SERVER_URL`. Do NOT use `localhost`.
NSSM service won't startRun wrapper script manually first. Check `C:\Logs\jupyter.err.log` for WSL2 path errors.
Kernel dies on GPU allocSet CUDA_VISIBLE_DEVICES=0,1 in config. Limit VRAM usage.Set HSA_OVERRIDE_GFX_VERSION to exact arch. Check VRAM limits.Ensure Docker Desktop → Settings → Resources → Advanced → GPU = Enabled
Open WebUI tool timeoutIncrease DASK_DISTRIBUTED__COMM_TIMEOUT=120s in Jupyter environment config.

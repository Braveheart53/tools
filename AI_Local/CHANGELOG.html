Change log

Version history

The AI_Local page set carries one version, stamped in the navigation strip of every page. This log records what changed in each revision, including what was deliberately left alone.

Versioning is semantic, X.Y.Z, with 0.0.1 as the first internal draft. Current version: v0.0.1.

Versioning scheme

What each component of the version number signifies for this page set.
ComponentIncrements whenExample
X — majorThe set is restructured, or guidance changes in a way that invalidates a previous configurationMoving the whole set off Open WebUI
Y — minorA page is added or removed, or a page gains substantial new materialAdding the build-and-test page
Z — patchCorrections, re-verified figures, new citations, styling fixesUpdating a model size after a requantisation
0.y.zPre-release. The set is an internal draft until 1.0.0v0.0.1, this revision

Individual assets carry their own version in their header comment, which moves independently of the set version. Shell scripts and Python modules shipped alongside the pages follow the same scheme.

Releases

v0.0.12026-10-18

First internal draft of the rebuilt page set

Added

  • local-code-build-test.html — the page that was missing from the set: how to let a locally hosted model generate code and then build and test it on local hardware through Open WebUI. Covers the choice between Pyodide, the Jupyter engine and Open Terminal; the full variable set for each; wiring a named mamba environment in by either route; CMake and MSVC builds; Qt, Veusz and GPU specifics for Python; and a twelve-step verification sequence.
  • ollama-model-selection.html — which models in the Ollama library are suited to local code and agent work, with every size, context window, capability label and published benchmark figure cited to its model page, and the memory and throughput arithmetic that decides whether a given tag will fit and run.
  • claude-sandbox-local-env.html — granting a sandboxed agent prompt access to local mamba environments: what an OS-enforced command sandbox restricts, how it differs from a container backend, the settings that grant environment access, and the denial checks that confirm a policy actually took effect.
  • monitoring-sizing.html — the four relations the existing monitoring install pages assume but never state: the disk cost of a retention window, what the scrape configuration actually ingests, the lower bound on a range-vector window that stops panels emptying intermittently, and the difference between a counter and a gauge when computing utilisation. Placed on its own page rather than duplicated as an appendix on each of the four monitoring pages.
  • index.html — a landing page for the set, generated from the page manifest so a future page appears here without an edit.
  • references.html — a single IEEE-format reference table for the whole set, generated from references.py, with a per-reference sourcing-confidence class and one shared access date.
  • CHANGELOG.html — this page.
  • A shared navigation strip on every page, giving one consistent route between all pages in the set plus the version stamp and a link to this change log.
  • A shared equation component (assets/equations.css, assets/equations.js) reproducing the equation and variable-definition pattern from Atomic Theory Atlas: a provenance pill, a Define variables disclosure that opens a symbol table with SI units, and an explicit step list behind every derived result.
  • KaTeX vendored into assets/katex/ so equations typeset with no network access, consistent with the rest of the set being usable offline.
  • A dark theme for the three pages that had none (assets/legacy-dark.css), plus a theme control on every page that lacked one.
  • scripts/probe_model_throughput.py — measures prefill and decode rates through the Ollama API and prints them against what the equations predict.
  • scripts/build_cpp.ps1 — a no-argument CMake build wrapper that discovers the MSVC toolchain with vswhere instead of a hard-coded toolset path, and caps parallelism from free memory.
  • config/ — ready-to-edit Open WebUI, Open Terminal and sandbox configuration files matching the worked examples on the pages.

Changed

  • Fifteen equations that were previously implicit in prose or absent entirely are now explicit blocks with variable tables: weight footprint, active parameters for a routed mixture of experts, key/value cache size, context budget, the memory-bandwidth decode ceiling, layer offload count, distributed per-token time, the RPC break-even condition, safe parallel job count, Amdahl speed-up, agent-loop wall clock, Prometheus disk and ingest rate, the rate() window condition, and counter-based utilisation.
  • The four pre-existing pages that carry an artifact iframe wrapper (Dockler_Jupyter_withGPU_Passthru_nssm, GPU_monitoring_setup, Jupyter_Server_Setup_wsl and the archived Jupyter_Code_Eval_Setup) have the duplicate <!DOCTYPE>, <html> and <body> elements removed, so each is now one valid document instead of two nested ones.
  • Every pre-existing page keeps its own stylesheet, layout, content and theme toggle unchanged. The rebuild adds the navigation strip and the shared stylesheets and nothing else, so no existing guide looks different from how it looked before.

Fixed

  • Grafan_Promethius_install_linux.html, Grafana_Prometheus_install_windows.html and the archived Windows_Exporter_Grafana_dashboard.html had no dark theme and no theme control. Both are now present, scoped so the light rendering is byte-for-byte unchanged.
  • Pages in the set had no way to reach each other; every page now carries the same navigation.
  • Citations were previously inline URLs or absent. All claims now resolve to a numbered row in one reference table.

Known limitations

  • The TERMINAL_SERVER_CONNECTIONS format is not published by the vendor, so the Open Terminal connection cannot be fully pre-seeded from the environment. Recorded on the build page.
  • Ollama tag pages do not state quantisation for most tags, so the footprint equation's bits-per-weight input is a library default rather than a published figure. The equation says so.
  • Per-compiler memory, the throughput realisation factor, runtime VRAM reservation, GGUF container overhead and the Prometheus series counts are planning estimates for this class of hardware, stated as ranges and flagged in each equation block.
  • The architectural quantities in the 24 GB worked fit are placeholders of a plausible shape, not values read from a model. The table says so and names the command that produces the real ones.

What was deliberately not changed

The rebuild was additive by design. Recorded here so a future revision does not assume these were oversights.

Deliberate non-changes in v0.0.1, with the reason each was left alone.
Left aloneReason
Each pre-existing page's own stylesheet, layout and theme toggle The seven existing guides each have a distinct look that works. Imposing one stylesheet would have changed every page's appearance for no reader benefit, and would have risked breaking page-specific behaviour such as the tab widget on the Windows Prometheus page
The technical content of the existing guides Nothing in them was found to be wrong. The rebuild adds the missing material rather than rewriting what was already correct
Hard-coded IP addresses (192.168.7.x) and absolute paths They document this deployment, and replacing them with placeholders would make the commands less useful to their actual reader
The binary installers and extracted exporter archives in the directory Outside the scope of a documentation rebuild, and the set's own Files_you_Will_need_that_areNot_here.txt already tracks what is missing
setup_info.txt as a scratch file It is a working notebook of commands, several marked as wrong in place. That record has value; the parts worth promoting were promoted into the new pages with citations, and the file stays as it is
The two pages under Archive/ Kept where they are, with the navigation strip and shared stylesheets added, so an archived page is still reachable and still readable in both themes

Candidates for the next revision

Not implemented, and listed for a decision rather than as a plan.

  • Measured throughput tables. Running probe_model_throughput.py across the shortlisted models on the actual nodes would replace the realisation factor with a measurement and turn the model-selection page's estimates into data.
  • A Grafana dashboard JSON for the agent loop. Prompt rate, decode rate, iteration count and build duration on one board, so the loop equation's terms can be watched instead of computed.
  • Worked architecture tables per shortlisted model, read from ollama show, replacing the placeholder layer and head counts in the 24 GB fit.
  • A single generated PDF of the whole set, bookmarked, with variable tables expanded. The print stylesheet already expands them; the remaining work is pagination.
  • An mcpo page. Exposing instrument control — Keysight or Lake Shore over VISA — to a local model as an MCP tool server is a natural extension of the build-and-test page and is currently only mentioned in passing.

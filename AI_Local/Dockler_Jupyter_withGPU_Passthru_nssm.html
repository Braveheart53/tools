Dockerized Jupyter GPU Server for Open WebUI

Complete, explicit guide to running Jupyter inside a containerized environment with direct GPU passthrough on Windows 10/11. Manages persistent services via NSSM + PowerShell. Uses Micromamba for fast dependency resolution. Fully separated NVIDIA CUDA and AMD ROCm deployment paths.

✅ Step 1: Windows WSL2 & Docker Prerequisites

1

Install WSL2 & Ubuntu Distro

PowerShell (Admin)
PS C:\> wsl --install -d Ubuntu-24.04
PS C:\> wsl --set-default-version 2
# Reboot if prompted
2

Install Docker Desktop (Windows Host)

  • Download from docker.com/products/docker-desktop
  • During install, check "Use WSL 2 instead of Hyper-V"
  • Launch Docker Desktop → Settings → General → Ensure "Use the WSL 2 based engine" is checked
  • Go to Resources → GPU Access and ensure your GPU is listed/enabled
3

Verify Docker WSL2 & GPU Integration

PowerShell & WSL2
# Windows Host:
PS C:\> docker info | grep -i "gpu"
PS C:\> wsl --list --running

# WSL2 Ubuntu Terminal:
$ docker run --rm hello-world  # Should pull and run via WSL2 engine
$ docker info | grep -i "nvidia\|rocm\|gpu"

🐳 Step 2: Docker GPU Passthrough Architecture

Modern Docker Desktop on Windows WSL2 automatically exposes the host GPU to containers. NVIDIA uses `--gpus all` (handled natively). AMD requires explicit device mounts and ROCm environment variables.

💚
NVIDIA Passthrough
Docker Desktop automatically routes `--gpus all` to the WSL2 backend. No host-side toolkit configuration required.
🔴
AMD Passthrough
Requires `--device /dev/kfd --device /dev/dri`, ROCm Win drivers, and `HSA_OVERRIDE_GFX_VERSION` to map architecture correctly.

💚 NVIDIA CUDA Container Path

1

Install Windows GPU Driver & Update WSL2

PowerShell (Admin)
# 1. Install NVIDIA GameReady/Studio Driver ≥ 535 (CUDA 12.x) or ≥ 550 (CUDA 12.4+)
PS C:\> winget install --id NVIDIA.Driver
# Reboot Windows after driver installation

# 2. Update WSL2 kernel to ensure GPU passthrough stability
PS C:\> wsl --update
PS C:\> wsl --shutdown
2

Create NVIDIA Container Stack

docker-compose.yml (NVIDIA)
# C:\Projects\jupyter-gpu-nvidia\docker-compose.yml
version: "3.8"
services:
  jupyter-gpu:
    image: "jupyter/pytorch-gpu-notebook:latest"
    container_name: jupyter-nvidia-gpu
    restart: unless-stopped
    ports:
      "- 8888:8888"
    devices:
      - /dev/nvidiactl:/dev/nvidiactl
      - /dev/nvidia-uvm:/dev/nvidia-uvm
      - /dev/nvidia0:/dev/nvidia0
    environment:
      "- NVIDIA_DRIVER_CAPABILITIES=compute,utility"
      "JUPYTER_TOKEN": "YOUR_GENERATED_TOKEN"
    volumes:
      "- ./notebooks:/home/jovyan/work"
      "- ./config:/home/jovyan/.jupyter"
    command: "/opt/conda/bin/start.sh lab --ip=0.0.0.0 --port=8888 --no-browser --allow-root"

      "- ./notebooks:/home/jovyan/work"

🛠️ Step 4: NSSM Service Bridge (PowerShell)

Use NSSM to run a PowerShell script that manages the Docker container lifecycle, handles logs, and auto-restarts on failure.

start-jupyter-docker.ps1 (NVIDIA Example)
# C:\Scripts\start-jupyter-docker.ps1
$env:DOCKER_DIR = "C:\Projects\jupyter-gpu-nvidia"
$LOG_DIR    = "C:\Logs"

New-Item $LOG_DIR -ItemType Directory -Force | Out-Null

while (-true) {
    Write-Host "[INFO] Starting Jupyter Docker Container..." -ForegroundColor Green
    Set-Location $env:DOCKER_DIR
    docker compose up -d --remove-orphans 2>&1 | Tee-Object -FilePath "$LOG_DIR\jupyter-docker.out.log" -Append

    # Health check loop (wait for Jupyter to respond)
    for ($i = 0; $i -lt 30; $i++) {
        Start-Sleep 2
        $status = curl.exe -s http://localhost:8888/api/status | Out-String
        if ($status.Contains("started")) { break; }
    }

    # Monitor container health (optional: use docker stats or exit loop if needed)
    Start-Sleep 300 # Check every 5 minutes
}
PowerShell (Service Install)
# Install NSSM if not present: https://nssm.cc/download
$NSSM_PATH = "C:\Program Files\nssm\bin\win64\nssm.exe"

PS C:\> & "$NSSM_PATH" install "JupyterGPUContainer" "powershell.exe" "-ExecutionPolicy Bypass -File C:\Scripts\start-jupyter-docker.ps1"
PS C:\> & "$NSSM_PATH" set "JupyterGPUContainer" AppStdout "C:\Logs\jupyter.out.log"
PS C:\> & "$NSSM_PATH" set "JupyterGPUContainer" AppStderr "C:\Logs\jupyter.err.log"
PS C:\> & "$NSSM_PATH" start "JupyterGPUContainer"

# Verify service status
PS C:\> Get-Service JupyterGPUContainer

🔗 Step 5: Open WebUI Integration

Open WebUI runs on Windows host via Docker Desktop. Connects to Jupyter container via `host.docker.internal`.

docker-compose.yml (Open WebUI Host)
# C:\Projects\open-webui\docker-compose.yml
version: "3.8"
services:
  open-webui:
    image: "ghcr.io/open-webui/open-webui:main"
    container_name: open-webui
    restart: unless-stopped
    ports:
      "- 3000:8080"
    volumes:
      "- open-webui-data:/app/backend/data"
    environment:
      # Point to Jupyter container via Docker internal DNS or host IP
      "JUPYTER_SERVER_URL": "http://host.docker.internal:8888"  # NVIDIA path
      # "JUPYTER_SERVER_URL": "http://host.docker.internal:8889"  # AMD path
      "JUPYTER_API_TOKEN": "YOUR_GENERATED_TOKEN"
      "WEBUI_AUTH": "true"
      "ENABLE_OAUTH_SIGNUP": "true"
    depends_on:
      - jupyter-gpu

  # Optional: Include Jupyter in same compose if managing on one host
# ... (copy NVIDIA or AMD stack here)

volumes:
  open-webui-data:
networks:
  win-docker-net:
    driver: nat

🔧 Step 7: Troubleshooting

IssueNVIDIA Path FixAMD Path FixDocker/NSSM Fix
GPU not available in containerRun `docker info | grep -i nvidia`. Ensure Docker Desktop GPU access is enabled.Verify `/dev/kfd` and `/dev/dri` exist in WSL2. Run `rocm-smi --showhw` first.Add `--gpus all` or explicit device mounts. Check Docker Desktop Resources → GPU Access.
Docker container exits immediatelyCheck logs: `docker logs jupyter-nvidia-gpu`. Missing CUDA/ROCm deps or volume mount errors.
NSSM service won't startRun PSScript manually first. Ensure `wsl --install` and Docker Desktop are configured for WSL2 backend.
Open WebUI tool timeoutIncrease `DASK_DISTRIBUTED__COMM_TIMEOUT=120s` in Jupyter environment config. Check CORS/network.

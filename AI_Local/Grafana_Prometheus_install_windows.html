Install & Use Prometheus + Grafana on Windows / WSL2

This page walks you through:

  • Installing Prometheus (the monitoring server) as a Windows service.
  • Installing windows_exporter (the Windows-native metric collector; replaces node_exporter on Windows hosts).
  • Installing node_exporter inside WSL2 Ubuntu if you prefer a Linux-side collector.
  • Installing Grafana via the official Windows MSI installer.
  • Configuring Prometheus to scrape metrics from Node A and remote nodes.
  • Adding Prometheus as a data source in Grafana and creating a simple dashboard.
  • Viewing the status of other nodes from Node A.
  • Optional: NVIDIA GPU metrics via nvidia_gpu_exporter.
Linux vs Windows approach at a glance:
On Linux you use systemd to manage services and node_exporter to collect metrics. On Windows you use NSSM (Non‑Sucking Service Manager) or native Windows Services for Prometheus, and windows_exporter (MSI) instead of node_exporter. Grafana installs as a standard Windows service via MSI.

1️⃣ Prerequisites

  • Windows 10 (1903+) or Windows 11 — 64-bit.
  • Administrator / PowerShell-as-Admin access.
  • Internet access to download packages.
  • Optional (WSL2 path): WSL2 with Ubuntu 22.04 installed (wsl --install).
  • PowerShell execution policy set to at least RemoteSigned:
    Set-ExecutionPolicy -Scope CurrentUser RemoteSigned
Which collector should I use?
  • windows_exporter (MSI) – easiest on Windows; collects CPU, RAM, disk, network, services. Recommended for Node A and any Windows worker nodes.
  • node_exporter (WSL2) – useful if you already run WSL2 and want Linux-style metrics; note that some metrics (disk, network) reflect the WSL2 virtual machine, not the physical host.

2️⃣ Install & Run Prometheus on Windows

2.1 Download Prometheus (Windows binary)

Download the latest Windows .zip from the official releases page. In PowerShell (as Administrator):

$VERSION = "2.53.0"   # change to latest from https://github.com/prometheus/prometheus/releases
$URL = "https://github.com/prometheus/prometheus/releases/download/v$VERSION/prometheus-$VERSION.windows-amd64.zip"

Invoke-WebRequest -Uri $URL -OutFile "$env:TEMP\prometheus.zip"
Expand-Archive -Path "$env:TEMP\prometheus.zip" -DestinationPath "C:\prometheus" -Force
# Flatten one level so binaries are directly in C:\prometheus
Get-ChildItem "C:\prometheus\prometheus-$VERSION.windows-amd64\*" | Move-Item -Destination "C:\prometheus\" -Force
Remove-Item "C:\prometheus\prometheus-$VERSION.windows-amd64" -Recurse -Force

2.2 Create a data directory

New-Item -ItemType Directory -Force -Path C:\prometheus\data

2.3 Write a basic prometheus.yml

Edit (or create) C:\prometheus\prometheus.yml:

global:
  scrape_interval: 15s
  evaluation_interval: 15s

scrape_configs:
  # windows_exporter running on THIS host (Node A) – port 9182 is the Windows default
  - job_name: 'node-a-windows'
    static_configs:
      - targets: ['localhost:9182']

  # Remote Windows nodes – replace IPs with your actual worker addresses
  - job_name: 'remote-nodes'
    static_configs:
      - targets:
          - '192.168.1.11:9182'   # Node B
          - '192.168.1.12:9182'   # Node C
          - '192.168.1.13:9182'   # Node D

  # Optional: NVIDIA GPU exporter on Node A (see section 8)
  # - job_name: 'gpu'
  #   static_configs:
  #     - targets: ['localhost:9835']
Port difference: On Linux node_exporter uses port 9100. On Windows, windows_exporter defaults to port 9182. Update any existing Grafana dashboards accordingly.

2.4 Install Prometheus as a Windows Service with NSSM

Download NSSM from https://nssm.cc/download, extract, and place nssm.exe at C:\nssm\nssm.exe. Then, in an Administrator PowerShell:

# Install and configure the Prometheus service
C:\nssm\nssm.exe install Prometheus "C:\prometheus\prometheus.exe"
C:\nssm\nssm.exe set Prometheus AppParameters `
    "--config.file=C:\prometheus\prometheus.yml --storage.tsdb.path=C:\prometheus\data"
C:\nssm\nssm.exe set Prometheus AppDirectory       "C:\prometheus"
C:\nssm\nssm.exe set Prometheus Start              SERVICE_AUTO_START
C:\nssm\nssm.exe set Prometheus AppStdout          "C:\prometheus\logs\stdout.log"
C:\nssm\nssm.exe set Prometheus AppStderr          "C:\prometheus\logs\stderr.log"

New-Item -ItemType Directory -Force -Path C:\prometheus\logs

Start-Service Prometheus
Get-Service Prometheus   # should show: Status = Running

2.5 Open Windows Firewall (inbound)

# Allow Prometheus UI / API from your LAN only
New-NetFirewallRule `
    -DisplayName "Prometheus" `
    -Direction Inbound `
    -Protocol TCP `
    -LocalPort 9090 `
    -RemoteAddress 192.168.1.0/24 `
    -Action Allow `
    -Profile Private

2.6 Verify Prometheus is running

Get-Service Prometheus   # Status: Running
# Open in browser:
Start-Process "http://localhost:9090"

You should see the Prometheus UI at http://localhost:9090.

3️⃣ Install the Metric Collector

Choose the approach that matches your setup. Both produce Prometheus-compatible metrics; use the tabs below.

windows_exporter MSI (all Windows nodes: A, B, C, D)

Download the latest .msi from https://github.com/prometheus-community/windows_exporter/releases and run it on every Windows node. In Administrator PowerShell:

$EXP_VER = "0.30.5"   # check for latest release
$MSI_URL = "https://github.com/prometheus-community/windows_exporter/releases/download/v$EXP_VER/windows_exporter-$EXP_VER-amd64.msi"

Invoke-WebRequest -Uri $MSI_URL -OutFile "$env:TEMP\windows_exporter.msi"

# Silent install – registers as the "windows_exporter" Windows Service automatically
msiexec /i "$env:TEMP\windows_exporter.msi" /quiet /norestart

The MSI registers and starts the service automatically. Verify on each node:

Get-Service windows_exporter   # Status: Running
# Metrics endpoint (default port 9182):
Invoke-RestMethod http://localhost:9182/metrics | Select-Object -First 20

Open the firewall so Prometheus on Node A can reach workers B, C, D (run on each worker):

# On NODE-B, C, D – allow scraping from Node A only
New-NetFirewallRule `
    -DisplayName "windows_exporter" `
    -Direction Inbound `
    -Protocol TCP `
    -LocalPort 9182 `
    -RemoteAddress 192.168.1.10 `
    -Action Allow `
    -Profile Private
Default collectors enabled by the MSI: cpu, logical_disk, memory, net, os, process, service, system, tcp, time. For GPU metrics, see Section 8.

node_exporter inside WSL2 Ubuntu

Open a WSL2 Ubuntu terminal and run:

VERSION=1.8.0
wget https://github.com/prometheus/node_exporter/releases/download/v${VERSION}/node_exporter-${VERSION}.linux-amd64.tar.gz
tar xvf node_exporter-${VERSION}.linux-amd64.tar.gz
sudo mv node_exporter-${VERSION}.linux-amd64 /opt/node_exporter
sudo ln -s /opt/node_exporter/node_exporter /usr/local/bin/node_exporter

Create a systemd service inside WSL2:

cat <<'EOF' | sudo tee /etc/systemd/system/node_exporter.service
[Unit]
Description=Prometheus Node Exporter
After=network-online.target

[Service]
ExecStart=/opt/node_exporter/node_exporter
Restart=always

[Install]
WantedBy=multi-user.target
EOF

sudo systemctl daemon-reload
sudo systemctl enable node_exporter
sudo systemctl start node_exporter

Verify from WSL2:

curl http://localhost:9100/metrics | head -n 20
Accessing WSL2 metrics from Windows: WSL2 runs on a virtual NIC. From Windows (or Prometheus on Node A), the WSL2 host is reachable at localhost:9100 because Windows 10/11 auto-forwards localhost ports to WSL2. If using a remote Prometheus, forward with netsh interface portproxy.

Add localhost:9100 to your prometheus.yml scrape targets in place of (or alongside) the windows_exporter entry.

4️⃣ Install Grafana on Windows

4.1 Download and run the MSI installer

The official Grafana MSI auto-installs as a Windows service. Download from https://grafana.com/grafana/download (choose Windows, OSS edition):

# In Administrator PowerShell – adjust version as needed
$GF_VER = "11.1.0"
$GF_URL = "https://dl.grafana.com/oss/release/grafana-$GF_VER.windows-amd64.msi"

Invoke-WebRequest -Uri $GF_URL -OutFile "$env:TEMP\grafana.msi"
Start-Process msiexec -ArgumentList "/i `"$env:TEMP\grafana.msi`" /quiet /norestart" -Wait

Grafana is installed to C:\Program Files\GrafanaLabs\grafana\ and registered as the Grafana Windows service, set to auto-start.

4.2 Start / verify the Grafana service

Start-Service Grafana
Get-Service Grafana      # Status: Running
# Or using sc.exe:
sc.exe query grafana     # Look for STATE : 4  RUNNING

4.3 Access the Grafana UI

Open a browser on Node A and navigate to http://localhost:3000.
Default login: admin / admin. You will be prompted to change the password on first login.

4.4 Reset admin password (if needed)

cd "C:\Program Files\GrafanaLabs\grafana\bin"
.\grafana-cli admin reset-admin-password yournewpassword

# Then restart the service to apply
Restart-Service Grafana

5️⃣ Add Prometheus as a Data Source in Grafana

  1. Log in to Grafana at http://localhost:3000.
  2. Click ⚙️ Configuration (gear icon) → Data Sources → Add data source.
  3. Select Prometheus from the list.
  4. Set the URL to http://localhost:9090 (Prometheus runs on the same Node A host).
  5. Leave Access as Server (default).
  6. Click Save & test. You should see a green Data source is working banner.
If you run Grafana on a machine other than Node A, replace localhost with Node A's IP address (192.168.1.10) and ensure the Windows Firewall rule from Step 2.5 allows traffic on port 9090.

6️⃣ Create a Dashboard to Visualise Nodes

6.1 Import a pre-built Windows dashboard (quickest)

Grafana has a community dashboard for windows_exporter. In the Grafana UI:

  1. Click + → Import.
  2. Enter dashboard ID 14694 (Windows Node dashboard for windows_exporter) and click Load.
  3. Select your Prometheus data source and click Import.

6.2 Build panels manually with PromQL

Click + → Dashboard → Add new panel, set the query dropdown to Prometheus, and enter queries like these:

# CPU % for Node A (windows_exporter metric – note the different metric name vs node_exporter)
100 - (avg by (instance) (rate(windows_cpu_time_total{mode="idle"}[5m])) * 100)

# Memory available % on Node A
(windows_os_physical_memory_free_bytes / windows_cs_physical_memory_bytes) * 100

# CPU % scoped to a specific remote node (e.g. Node B at 192.168.1.11)
100 - (avg by (instance) (rate(windows_cpu_time_total{instance="192.168.1.11:9182",mode="idle"}[5m])) * 100)
Metric name change: On Linux, node_exporter uses node_cpu_seconds_total. On Windows, windows_exporter uses windows_cpu_time_total. Update any copied Linux queries accordingly.

6.3 Node UP/DOWN status table

up{job="remote-nodes"}

Set the visualization to Table, enable Color mode → Status, and you get a green/red view of every node's health.

7️⃣ Check Node Status from Node A via PowerShell

Instead of the Linux bash script, use PowerShell to query the Prometheus API from Node A:

# Save as Check-NodeStatus.ps1 and run from Node A
$PrometheusBase = "http://localhost:9090"
$Nodes = @(
    @{ name="Node-B"; instance="192.168.1.11:9182" },
    @{ name="Node-C"; instance="192.168.1.12:9182" },
    @{ name="Node-D"; instance="192.168.1.13:9182" }
)

foreach ($node in $Nodes) {
    $query = [uri]::EscapeDataString("up{instance=`"$($node.instance)`"}")
    $uri   = "$PrometheusBase/api/v1/query?query=$query"
    try {
        $resp   = Invoke-RestMethod -Uri $uri -ErrorAction Stop
        $status = $resp.data.result[0].value[1]
        if ($status -eq "1") {
            Write-Host "✅ $($node.name) ($($node.instance)) is UP"
        } else {
            Write-Host "❌ $($node.name) ($($node.instance)) is DOWN or not scraped"
        }
    } catch {
        Write-Host "⚠️  $($node.name) – query failed: $_"
    }
}

Run it with:

.\Check-NodeStatus.ps1

8️⃣ Optional: NVIDIA GPU Metrics on Windows

Use nvidia_gpu_exporter — it calls nvidia-smi.exe directly and works natively on Windows without Docker or Linux. It listens on port 9835 by default.

8.1 Download and install

# In Administrator PowerShell – check for latest release at
# https://github.com/utkuozdemir/nvidia_gpu_exporter/releases
$GPU_EXP_VER = "1.2.1"
$GPU_URL = "https://github.com/utkuozdemir/nvidia_gpu_exporter/releases/download/v$GPU_EXP_VER/nvidia_gpu_exporter_${GPU_EXP_VER}_windows_x86_64.zip"

Invoke-WebRequest -Uri $GPU_URL -OutFile "$env:TEMP\gpu_exporter.zip"
Expand-Archive -Path "$env:TEMP\gpu_exporter.zip" -DestinationPath "C:\gpu-exporter" -Force

8.2 Install as a Windows service with NSSM

C:\nssm\nssm.exe install NvidiaGPUExporter "C:\gpu-exporter\nvidia_gpu_exporter.exe"
C:\nssm\nssm.exe set NvidiaGPUExporter AppDirectory "C:\gpu-exporter"
C:\nssm\nssm.exe set NvidiaGPUExporter Start SERVICE_AUTO_START

Start-Service NvidiaGPUExporter
Get-Service NvidiaGPUExporter   # Status: Running

8.3 Verify GPU metrics are exposed

Invoke-RestMethod http://localhost:9835/metrics | Select-Object -First 20
# Should include lines like: nvidia_smi_utilization_gpu_ratio, nvidia_smi_memory_used_bytes, etc.

8.4 Add the GPU exporter to prometheus.yml

Add a new scrape job in C:\prometheus\prometheus.yml and restart Prometheus:

  - job_name: 'gpu'
    static_configs:
      - targets: ['localhost:9835']
Restart-Service Prometheus

8.5 Query GPU utilisation in Grafana

# GPU utilisation % on Node A
nvidia_smi_utilization_gpu_ratio * 100

# GPU memory used on a specific node
nvidia_smi_memory_used_bytes{instance="192.168.1.11:9835"}

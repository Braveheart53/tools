Prometheus & Grafana setup
for a multi-node llama-server cluster

This walkthrough shows how to monitor a Windows 11 multi-node llama.cpp deployment where NODE-A runs llama-server in router mode, Prometheus, Grafana, nginx, and Open WebUI, while worker nodes expose RPC and Windows host metrics.

Assumes: Prometheus port 9090 · Grafana port 3000 · windows_exporter port 9182 · llama-server port 8080 · RPC workers port 50052.

Architecture overview

ComponentRuns wherePurpose
llama-server (router mode)NODE-ASingle inference/control endpoint; routes requests to named model presets via RPC workers.
rpc-serverNODE-B/C/DWorker nodes contributing compute to the model loaded by NODE-A.
PrometheusNODE-AScrapes metrics from windows_exporter, Prometheus itself, and per-model llama-server endpoints.
GrafanaNODE-ABuilds dashboards for tokens/sec, queue depth, CPU, memory, and host visibility.
windows_exporterNODE-A/B/C/DExports CPU, memory, disk, and OS metrics from each Windows machine.
nginxNODE-AReverse proxy for Open WebUI only. Does not distribute RPC workers.
In router mode, Prometheus scrapes /metrics?model=<model-id> on NODE-A per named model preset. Grafana panels for Nemotron, Mistral, and Llama 3.1 should each use a separate Prometheus job.

Prerequisites

On NODE-A

  • Windows 11 administrative access
  • llama-server.exe already working manually
  • NSSM at C:\tools\nssm.exe
  • Prometheus extracted to C:\Prometheus
  • Grafana installed via MSI or extracted to C:\Grafana
  • C:\logs folder created

On NODE-B/C/D

  • RPC service reachable on port 50052
  • windows_exporter installed on port 9182
  • Firewall allows NODE-A to scrape port 9182

Install windows_exporter on all nodes

1Download the latest windows_exporter MSI from GitHub and install on NODE-A, B, C, and D.

2Confirm it is reachable locally on each node:

http://localhost:9182/metrics

3From NODE-A, confirm each worker is reachable over the network:

Test-NetConnection 192.168.7.28 -Port 9182
Test-NetConnection 192.168.7.45 -Port 9182
Test-NetConnection 192.168.7.181 -Port 9182
If port 9182 is blocked, Prometheus will mark the target DOWN. Fix Windows Firewall on each worker before configuring Prometheus scrape jobs.

Install Prometheus on NODE-A

1Download Prometheus for Windows from prometheus.io and extract to C:\Prometheus.

2Create C:\Prometheus\prometheus.yml:

prometheus.yml

global:
  scrape_interval: 15s
  evaluation_interval: 15s

rule_files:

scrape_configs:
  - job_name: "AI_Nodes"
    static_configs:
      - targets:
          - 192.168.7.27:9182
          - 192.168.7.28:9182
          - 192.168.7.45:9182
          - 192.168.7.181:9182

  - job_name: "llamacpp_nemotron3"
    metrics_path: /metrics
    params:
      model: [ "nemotron3" ]
    static_configs:
      - targets:
          - 192.168.7.27:8080

  - job_name: "llamacpp_mistral"
    metrics_path: /metrics
    params:
      model: [ "mistral-medium" ]
    static_configs:
      - targets:
          - 192.168.7.27:8080

  - job_name: "llamacpp_llama31_8b"
    metrics_path: /metrics
    params:
      model: [ "llama31-8b" ]
    static_configs:
      - targets:
          - 192.168.7.27:8080

  - job_name: "prometheus"
    static_configs:
      - targets:
          - 127.0.0.1:9090

Test the config

cd C:\Prometheus
.\prometheus.exe --config.file="C:\Prometheus\prometheus.yml" --config.check
If --config.check is not supported, run Prometheus normally and check for YAML errors on startup. Every - job_name block must have its children indented under it with 2-space indentation.

Install Prometheus as a Windows service (NSSM)

$svcArgs = '--config.file="C:\Prometheus\prometheus.yml"'

C:\tools\nssm.exe install Prometheus `
  "C:\Prometheus\prometheus.exe" $svcArgs

C:\tools\nssm.exe set Prometheus AppDirectory C:\Prometheus
C:\tools\nssm.exe set Prometheus Start SERVICE_AUTO_START
C:\tools\nssm.exe set Prometheus AppStdout C:\logs\prometheus.log
C:\tools\nssm.exe set Prometheus AppStderr C:\logs\prometheus-err.log

Start-Service Prometheus

To apply any future changes to prometheus.yml:

Restart-Service Prometheus

Install Grafana on NODE-A

1Download the Grafana Windows MSI from grafana.com and run it. The MSI automatically creates and starts a Grafana Windows service.

2Open http://localhost:3000. Grafana should be accessible immediately after MSI installation.

Change the default port

Edit C:\Program Files\GrafanaLabs\grafana\conf\custom.ini (create it by copying sample.ini if it does not exist):

[server]
http_port = 3001
Restart-Service grafana
Always use custom.ini, not defaults.ini. This ensures Grafana upgrades do not overwrite your settings.

Grafana user management and access control

First login and mandatory password change

On first visit to http://localhost:3000, log in with the default credentials:

  • Username: admin
  • Password: admin

Grafana immediately prompts you to change the admin password. Set a strong password and click Save. This must be completed before proceeding.

Never leave the default admin/admin credentials in a multi-user or network-accessible environment.

Grafana roles explained

RolePermissions
Grafana Admin (Server Admin)Create/delete users, manage all organizations, configure plugins and data sources server-wide. Only the initial admin account has this.
Organization AdminManage data sources, teams, and users within one organization. Assign roles to members.
EditorCreate, edit, and delete dashboards, panels, and alert rules. Cannot manage users.
ViewerView dashboards only. Cannot edit any content.

Create a new user

  1. Sign in as admin.
  2. Go to Administration → Users and access → Users.
  3. Click New user.
  4. Fill in Name, Email, Username, and Password.
  5. Click Create user.

The new user is automatically assigned Viewer in the default organization.

Change a user's role

  1. Go to Administration → Users and access → Users.
  2. Click the user to update.
  3. Scroll to the Organizations section at the bottom.
  4. Click the role dropdown (Viewer / Editor / Admin) and select the desired role.
  5. The change takes effect on the user's next page load.

Grant or remove Server Admin privileges

  1. Go to Administration → Users and access → Users.
  2. Click the user.
  3. In the Permissions section, next to Grafana Admin, click Change.
  4. Select Yes to grant or No to revoke, then confirm.
Grant Server Admin only to trusted accounts. Server Admins bypass all dashboard and folder permission rules.

Disable or delete a user

  1. Go to Administration → Users and access → Users.
  2. Click the user.
  3. Disable: click Disable user. The account is retained but the user cannot sign in.
  4. Delete: click Delete user. This is permanent and irreversible.

Reset the admin password (CLI)

If the admin password is lost, use grafana-cli from an elevated PowerShell:

cd "C:\Program Files\GrafanaLabs\grafana\bin"
grafana-cli admin reset-admin-password NEW_PASSWORD_HERE
Restart-Service grafana
If Grafana is installed to a custom path, prefix the command with --homepath "C:\your\grafana\path" before the admin subcommand.

Create teams and assign team permissions

  1. Go to Administration → Users and access → Teams.
  2. Click New team, give it a name (e.g., llm-ops), and click Create.
  3. On the team page click Add member and add users.
  4. Go to a dashboard folder → Manage permissions → Add permission → Team → select your team → set role → click Save.

Dashboard and folder permissions

  1. In the left sidebar click Dashboards.
  2. Hover over a folder or dashboard and click its kebab menu (⋮) or the gear icon.
  3. Select Manage permissions.
  4. Click Add permission, choose User, Team, or a role, set the access level, and click Save.
The most permissive rule always wins. Removing a default role from a folder does not restrict a Server Admin.

Disable anonymous access

Confirm no anonymous access is allowed in custom.ini:

[auth.anonymous]
enabled = false

If enabled = true is present, any browser on your LAN can view dashboards without a password.

Restart-Service grafana

Add Prometheus as a Grafana data source

  1. Open Grafana at http://localhost:3000.
  2. Go to Connections → Data sources.
  3. Click Add data source and select Prometheus.
  4. Set URL to http://localhost:9090.
  5. Leave authentication off unless you added a reverse proxy or auth layer.
  6. Click Save & test.
If Grafana cannot reach Prometheus, verify http://localhost:9090 works in a browser on NODE-A first, then check the Prometheus service state and firewall.

Recommended dashboard layout

Organize the dashboard into three logical rows:

  • Row 1 — Cluster health: target count, Prometheus health, RPC node reachability.
  • Row 2 — Model activity: tokens/sec, requests, queue depth per preset.
  • Row 3 — Host resources: CPU and memory per node.
PanelTypePurpose
Prometheus targets upStatQuick signal all scrape jobs are healthy.
NODE-A CPU usageTime seriesControl-plane load on the master node.
NODE-A memory usageTime seriesRAM pressure on the router machine.
Nemotron request activityTime seriesModel-specific traffic from router mode.
Mistral request activityTime seriesCompare load between models.
All nodes CPU by instanceTime seriesSee whether all workers are under load.
All nodes memory usedBar gaugeWhich worker has highest RAM pressure.

Step-by-step panel creation

Panel 1 — Prometheus target health

  1. Create a new dashboard and click Add visualization.
  2. Select your Prometheus data source.
  3. Choose a Stat panel type.
  4. Enter the query and click Run query:
sum(up)

Rename the panel to Targets Up. A value equal to your total job count means all scrape targets are healthy.

Panel 2 — Node CPU usage (%)

Create a Time series panel with:

100 - (avg by (instance) (rate(windows_cpu_time_total{mode="idle"}[5m])) * 100)

Set legend to {{instance}}. Unit: Percent (0–100).

Panel 3 — Node memory usage (%)

(1 - (windows_os_physical_memory_free_bytes / windows_cs_physical_memory_bytes)) * 100

Unit: Percent (0–100). Legend: {{instance}}.

Panel 4 — Per-model metrics

Filter by Prometheus job label. In Grafana Explore, browse metric names beginning with llama_ to confirm the exact names your build exports:

{job="llamacpp_nemotron3"}
llama.cpp metric names can change between builds. Always verify exact names by opening http://192.168.7.27:8080/metrics?model=nemotron3 directly before writing panel queries.

Panel 5 — Request rate per model

rate(llama_requests_total{job="llamacpp_nemotron3"}[5m])

Duplicate this panel for each model, changing only the job label. Unit: ops/sec.

Panel 6 — Tokens per second

rate(llama_tokens_total{job="llamacpp_nemotron3"}[5m])

Format as ops/sec or a custom unit. Duplicate for each model preset.

Inspect raw metrics before building panels

Open these URLs in a browser on NODE-A to see every metric name available:

http://192.168.7.27:8080/metrics?model=nemotron3
http://192.168.7.27:8080/metrics?model=mistral-medium
http://192.168.7.27:8080/metrics?model=llama31-8b
http://192.168.7.27:9182/metrics
http://127.0.0.1:9090/metrics

Troubleshooting

Prometheus target is DOWN

  • Check Windows Firewall on the target machine.
  • Confirm the exporter service is running.
  • Open the target URL directly in a browser from NODE-A.

Grafana shows no data

  • Open Grafana Explore and browse metric names to confirm they exist.
  • Verify the job label in your query matches exactly what is in prometheus.yml.
  • Confirm the Prometheus scrape target is UP.

llama-server model panels are empty

  • Confirm params.model in prometheus.yml exactly matches the section name in your Ollama_models.ini.
  • Open /metrics?model=<name> directly and verify metrics are returned.
  • Ensure --metrics is enabled in the llama-server service definition.

prometheus.yml config errors

  • Use two-space indentation throughout the file.
  • Every - job_name entry needs its child keys indented under it.
  • Each job name must be unique across the entire file.

Grafana login / password issues

  • Use grafana-cli admin reset-admin-password NEWPASS from an elevated prompt in the bin folder, then restart the Grafana service.
  • If the Grafana service fails to start after installation, check C:\logs\grafana.log for the cause.

Maintenance workflow

  1. Add or change a model preset in Ollama_models.ini.
  2. Add a matching Prometheus scrape job using params.model.
  3. Run .\prometheus.exe --config.file=... --config.check.
  4. Restart the Prometheus service: Restart-Service Prometheus.
  5. Add or duplicate a Grafana panel for the new job.
  6. Verify new time series appear in Grafana Explore.

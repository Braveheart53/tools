AI_Local · v0.0.4

Running AI on your own hardware, end to end

A working set for deploying language models across a home or lab network: serving them, distributing them across several machines when one is not enough, monitoring what the hardware is doing, and — the part this revision adds — letting a model write, build and test code on machines you own, with nothing leaving the network.

Scientific and code-building work is the focus. Every page cites its sources to a numbered row in one reference table, every equation carries a variable table with units, and every figure that is an estimate rather than a citation says so.

Start here

The set assumes one inference host with optional worker nodes. If you are building this from nothing, the order below gets you to a working loop with the fewest dead ends.

  1. Pick a model that fits. Model selection has the criteria and the memory arithmetic. Doing this first avoids installing a stack around a model your card cannot hold.
  2. Serve it. Ollama alone on one machine, or llama.cpp with RPC workers when the model is larger than any single card.
  3. Give it a shell. Local build and test covers Open Terminal, the Jupyter engine and wiring in a mamba environment.
  4. Decide the boundary. Sandboxed access to local environments covers the other containment model, for work that needs the host itself.
  5. Watch it. The Prometheus and Grafana pages, which is how you find out a model quietly spilled to system RAM.

What this revision adds

The set previously stopped at serving and monitoring a model. Three pages now cover the loop from a prompt to a passing test suite:

  • Execution backends and their variables, quoted verbatim
  • Named mamba environments reached from a sandbox
  • C++ and Python build and test paths
  • Model selection with the fit arithmetic shown
  • What each containment model actually contains

Conventions used across the set

Reading conventions. The provenance pills and the variable-table disclosure follow the pattern established in the Atomic Theory Atlas page set in this repository.
ConventionMeaning
StatedQuoted from a cited source. Nothing was algebraically manipulated
Derived hereAlgebra or a numerical evaluation performed on these pages. Always followed by an explicit step list
Measured valueA tabulated experimental or defined number
primaryA normative or first-party specification: vendor documentation, a standards body, a reference manual
vendorFirst-party but commercial and revised without notice: a model card, a product page
estimateA planning figure for this class of hardware, stated as a range. Measure it before relying on it
Define variables buttonOpens a table of every symbol in the equation with its SI or stated unit. Variable tables are always expanded when a page is printed
Citation [n]Links to row n of the reference table

Offline by design

Every page in the set opens from a local disk with no network access. KaTeX[31] is vendored into assets/katex/ rather than loaded from a content-delivery network — it has no dependencies and is designed to be bundled with a site's own resources — and nothing in the set uses browser storage — so the pages also render correctly inside a sandboxed frame, where storage access throws. The theme follows the operating-system preference and can be overridden for the current page view.

Files you will need that are not in the repository

Installers specific to your hardware — CUDA, the Vulkan SDK, Docker Desktop, the Grafana MSI — are listed in Files_you_Will_need_that_areNot_here.txt alongside these pages[32].

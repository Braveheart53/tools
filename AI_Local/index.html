Braveheart53 / tools · v0.0.3

Local AI, and the engineering work it is for

This repository is a working set for deploying language models across your own hardware and then pointing them at real engineering code. It is not a collection of unrelated utilities: everything in it either builds one Python environment, runs inside that environment, or documents the physics behind something that does.

That single fact is what the page below is organised around. 5 stages take you from an empty machine to a model that writes, compiles and tests code in your environment, and every one of the 18 projects in this repository has a place in that sequence.

If you only read one thing: do stage 0 before anything else. Every Python tool here is written against one named mamba environment, and the local model in stage 2 is explicitly told to use it. Skipping it produces a model that reports libraries are missing when it is simply looking at the wrong interpreter, and that failure is tedious to diagnose from the other end.

1. Start with what you have

The flow below adapts to the hardware you are working with. Pick the closest shape; stages that do not apply to it are dimmed rather than hidden, so you can still see what you are skipping and why.

One machine. Monitoring is optional on one machine: ollama ps answers the question a dashboard would. Skip stage 3 until you have a second node.

Model sizing: Pick the largest tag that leaves roughly a third of VRAM free for the key/value cache. Below 16 GB, prefer a small model that fits entirely over a large one that spills.

Two machines. This is the shape where separating inference from execution first pays off, and where monitoring starts to earn its keep.

Model sizing: Keep the model on whichever machine has the most VRAM and put the execution sandbox on the other, so a build cannot evict the model from memory.

Four machines. The llama.cpp RPC guide and the monitoring pages are written for exactly this layout.

Model sizing: Distribution is for escaping a spill, not for adding bandwidth. Check the break-even condition before switching a worker on.

No shape selected, so every stage is shown. Choosing one dims the stages it does not need.

2. The implementation flow

Each stage produces the thing the next one needs, so the order is a dependency chain rather than a preference. Every stage ends with a checkpoint that is a command or an observation, not a feeling — if the checkpoint does not pass, the next stage will fail in a way that is harder to diagnose.

3. Which model, and will it fit?

Stage 1 turns on two questions that have to be answered together: which model to run, and whether your card can actually hold it. Reading someone else’s worked example is a poor substitute for either, so both are evaluated here against your own hardware. The arithmetic is the same as the model selection page, which shows every derivation; the figures are the same ones that page cites, because both are generated from one catalogue.

A model “fits” here when its weight file, the runtime reservation and at least 1 GB of cache all sit on the card. A model that is technically resident but cannot hold a useful prompt is not a fit.

Context a card can hold, once weights and runtime are placed

Derived here
\[ L_{\max} \;=\; \left\lfloor \frac{V_{\text{tot}} - S_{w} - V_{\text{rt}}}{2\,n_{\ell}\,n_{kv}\,d_{h}\,n_{\text{seq}}\,b_{kv}} \right\rfloor \]

The window a model page advertises is what its weights were trained to attend over. This is what your hardware can allocate, which is the number that constrains your work.

  1. Autoregressive attention caches one key vector and one value vector per token per layer, so one token of context costs \( 2\,n_{\ell}\,n_{kv}\,d_{h}\,b_{kv} \) bytes, times \( n_{\text{seq}} \) for concurrent sequences that each keep their own cache.
  2. The cache shares the device with the weights \( S_{w} \) and the runtime's own allocations \( V_{\text{rt}} \), so the bytes available to it are \( V_{\text{tot}} - S_{w} - V_{\text{rt}} \).
  3. Divide the remainder by the per-token cost and take the floor, since a partial token cannot be cached.
  4. Treat the result as an upper bound. Allocators fragment, and on Windows the display driver can page VRAM out from under the runtime.
  5. Each step above is worked in full, with the intermediate forms, on the model selection page.
Symbols in the context-budget relation. Read the architectural quantities from ollama show <tag>; the defaults below are a plausible shape for a 30B-class model and are not a measurement.
SymbolMeaningUnit
\(L_{\max}\)Largest context that fits once weights and runtime are placedtoken
\(V_{\text{tot}}\)Total device memory on the acceleratorB
\(S_{w}\)Weight footprint, the size the model tag listsB
\(V_{\text{rt}}\)Runtime, driver and compute-buffer reservationB
\(n_{\ell}\)Transformer layersdimensionless
\(n_{kv}\)Key/value heads per layerdimensionless
\(d_{h}\)Head dimensiondimensionless
\(n_{\text{seq}}\)Concurrent sequences, --parallel or OLLAMA_NUM_PARALLELdimensionless
\(b_{kv}\)Bytes per cached element, set by OLLAMA_KV_CACHE_TYPEB

The bandwidth cliff is the thing this is protecting you from. If the result is negative, the weights do not fit and llama.cpp or Ollama will place some layers in system RAM. The same weight set streams roughly nine times slower from system RAM than from VRAM, so a smaller model fully resident beats a larger one that spills — essentially always. Confirm residency with ollama ps rather than assuming it.

7. How to read the documentation here

The HTML page sets in this repository share one set of conventions, borrowed from the Atomic Theory Atlas and applied to the AI_Local pages during the v0.0.1 rebuild. They are worth two minutes before reading a page in anger.

Reading conventions shared by the AI_Local pages and the Educational page sets.
MarkerMeans
StatedQuoted from a cited source. Nothing was algebraically manipulated
Derived hereAlgebra or a numerical evaluation performed on the page. Always followed by an explicit step list
Measured valueA tabulated experimental or defined number
primaryA normative or first-party specification: vendor documentation, a standards body, a reference manual
vendorFirst-party but commercial and revised in place without notice: a model card, a product page
Define variables buttonOpens a table of every symbol in the equation with its SI or stated unit. Always expanded when a page is printed
Citation [n]Links to row n of that page set's reference table

Offline by design

Every HTML page in this repository opens from local disk with no network access. KaTeX is vendored rather than loaded from a content-delivery network, and nothing uses browser storage, so the pages also render correctly inside a sandboxed frame. The theme follows your operating-system preference and can be overridden for the current page view.

Where the numbers come from

Figures in the AI_Local pages are either cited to a source or shown with their derivation. The ones that are neither — planning estimates for a class of hardware, such as per-compiler memory or the throughput realisation factor — are listed together with their values and how to measure them on the references page. That list exists so an estimate is never mistaken for a citation.
